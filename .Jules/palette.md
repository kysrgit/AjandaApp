## 2024-05-24 - Interactive Custom UI Elements Lack Semantic Accessibility
**Learning:** This application implements custom interactive elements using non-semantic tags (e.g., `<div class="workout-badge clickable">`) rather than native `<button>` elements. These elements completely lack default keyboard accessibility, meaning users navigating with a keyboard or screen reader cannot focus on or interact with them natively.
**Action:** When working on this application, actively scan for `div` or `span` elements acting as buttons or links. For each, ensure `role="button"`, `tabindex="0"`, and `keydown` event listeners (handling 'Enter' and ' ') are manually implemented to restore standard accessibility behavior, as these are not provided for free by the framework. Additionally, ensure global focus states like `*:focus-visible` are defined so keyboard navigation is visually trackable.
